# Requirements Document: Mini Video Editor

## Introduction

The Mini Video Editor is a web-based GUI component that enables users to format horizontally-recorded video clips into vertical (9:16) format with repositionable webcam overlays. After the existing clip generation pipeline produces highlight clips, users can opt to format these clips to vertical aspect ratio by selecting and positioning a detected webcam region. The system auto-detects the facecam location, allows manual adjustment, previews the result, and applies the same placement consistently across all generated clips before replacing the originals with vertically-formatted versions.

## Glossary

- **Source_Clip**: The original horizontally-recorded video clip (typically 16:9 aspect ratio) generated by the clip extraction pipeline.
- **Vertical_Canvas**: A 9:16 aspect ratio output frame (1080×1920 pixels) composed of a facecam region (top) and gameplay region (bottom).
- **Facecam_Region**: The detected or manually-selected rectangular area in the source clip containing the user's face/webcam feed.
- **Facecam_Detector**: The system component that uses FFmpeg cropdetect to automatically locate the facecam region in the source clip.
- **Facecam_Placement**: The position and size of the facecam within the vertical canvas (always in the top region).
- **Gameplay_Region**: The lower portion of the vertical canvas (approximately 65% of height) where the source video content is displayed.
- **Mini_Editor**: The web GUI interface that allows users to view, detect, adjust, and confirm facecam placement.
- **Vertical_Formatter**: The backend system that applies the confirmed facecam placement to all clips and generates vertically-formatted output files.
- **Clip_Batch**: A collection of multiple highlight clips generated from a single source video.
- **Format_to_Vertical_Prompt**: The UI notification that appears after clip generation, offering users the option to format clips to vertical.
- **Preview_Pane**: The UI component displaying a real-time preview of how the vertical output will appear with the current facecam placement.
- **Adjustment_Controls**: UI elements (sliders, buttons, or drag handles) that allow users to modify the detected facecam position and size.
- **Confidence_Score**: A numerical value (0.0–1.0) indicating how confident the auto-detection is in the identified facecam region.
- **Fallback_Fill**: A blurred and cropped version of the gameplay video used to fill the top region when facecam detection fails.

## Requirements

### Requirement 1: Format to Vertical Prompt

**User Story:** As a user who has just generated highlight clips, I want to be prompted to format them to vertical, so that I can easily access the vertical formatting feature without navigating menus.

#### Acceptance Criteria

1. WHEN clip generation completes successfully, THE System SHALL display a "Format to Vertical" prompt to the user.
2. THE Prompt SHALL include a clear call-to-action button labeled "Format to Vertical" or similar.
3. THE Prompt SHALL allow the user to dismiss it without proceeding to the Mini_Editor.
4. WHEN the user clicks the "Format to Vertical" button, THE System SHALL open the Mini_Editor interface.
5. THE Prompt SHALL appear only after all clips have been generated and are ready for processing.

### Requirement 2: Mini Editor Interface Display

**User Story:** As a user opening the Mini Editor, I want to see a clear interface showing the source clip and vertical preview, so that I can understand how my clips will look in vertical format.

#### Acceptance Criteria

1. THE Mini_Editor SHALL display a horizontal preview pane showing the Source_Clip at its original aspect ratio.
2. THE Mini_Editor SHALL display a vertical preview pane showing the Vertical_Canvas with the current Facecam_Placement.
3. THE Mini_Editor SHALL display the Facecam_Region in the horizontal preview with a visible highlight (e.g., bounding box, overlay, or selection indicator).
4. THE Mini_Editor SHALL display the Gameplay_Region in the vertical preview showing how the source content will appear in the bottom portion.
5. THE Mini_Editor SHALL display the Facecam_Region in the vertical preview showing how the facecam will appear in the top portion.
6. THE Mini_Editor interface SHALL be responsive and usable on desktop browsers (minimum 1024×768 resolution).
7. THE Mini_Editor SHALL display the Confidence_Score of the auto-detected facecam region to the user.

### Requirement 3: Automatic Facecam Detection

**User Story:** As a user, I want the system to automatically detect my facecam region, so that I don't have to manually select it from scratch.

#### Acceptance Criteria

1. WHEN the Mini_Editor opens, THE Facecam_Detector SHALL analyze the Source_Clip to locate the Facecam_Region.
2. THE Facecam_Detector SHALL use FFmpeg cropdetect to identify candidate regions in the source video.
3. THE Facecam_Detector SHALL validate detected regions against configured area fraction constraints (minimum 4%, maximum 30% of frame area).
4. THE Facecam_Detector SHALL classify the detected region into one of four corners: top-left, top-right, bottom-left, or bottom-right.
5. THE Facecam_Detector SHALL compute a Confidence_Score (0.0–1.0) based on the frequency of the most-common detected crop region.
6. IF a valid Facecam_Region is detected, THE System SHALL display it in both preview panes with the Confidence_Score.
7. IF no valid Facecam_Region is detected, THE System SHALL display a message indicating detection failed and offer manual selection or fallback options.

### Requirement 4: Manual Facecam Region Adjustment

**User Story:** As a user, I want to adjust the auto-detected facecam region if it's not quite right, so that I can ensure the facecam is positioned exactly where I want it.

#### Acceptance Criteria

1. THE Mini_Editor SHALL provide Adjustment_Controls to modify the Facecam_Region position and size.
2. THE Adjustment_Controls SHALL allow the user to adjust the X position (horizontal offset) of the facecam within the source clip.
3. THE Adjustment_Controls SHALL allow the user to adjust the Y position (vertical offset) of the facecam within the source clip.
4. THE Adjustment_Controls SHALL allow the user to adjust the width of the Facecam_Region.
5. THE Adjustment_Controls SHALL allow the user to adjust the height of the Facecam_Region.
6. WHEN the user adjusts any parameter, THE Preview_Pane SHALL update in real-time to reflect the new Facecam_Placement.
7. THE Adjustment_Controls SHALL enforce minimum and maximum bounds to prevent invalid regions (e.g., regions extending beyond the source frame).
8. THE Adjustment_Controls SHALL provide visual feedback (e.g., highlighting, error messages) when the user attempts to create an invalid region.

### Requirement 5: Real-Time Preview of Vertical Output

**User Story:** As a user adjusting the facecam placement, I want to see a real-time preview of the vertical output, so that I can confirm the placement looks correct before applying it.

#### Acceptance Criteria

1. THE Preview_Pane SHALL display a 9:16 vertical canvas representation.
2. THE Preview_Pane SHALL show the Facecam_Region scaled and positioned in the top portion of the canvas.
3. THE Preview_Pane SHALL show the Gameplay_Region (source video content) scaled and positioned in the bottom portion of the canvas.
4. WHEN the user adjusts the Facecam_Region, THE Preview_Pane SHALL update within 500 milliseconds to reflect the new placement.
5. THE Preview_Pane SHALL maintain the correct aspect ratio and proportions of both the facecam and gameplay regions.
6. THE Preview_Pane SHALL display a black background fill in any empty space (e.g., letterboxing).
7. IF facecam detection failed and a Fallback_Fill is being used, THE Preview_Pane SHALL display the blurred gameplay fill in the top region.

### Requirement 6: Facecam Placement Confirmation

**User Story:** As a user satisfied with the facecam placement, I want to confirm my selection, so that the system can apply it to all clips.

#### Acceptance Criteria

1. THE Mini_Editor SHALL display a "Confirm" or "Apply" button that the user can click to confirm the Facecam_Placement.
2. WHEN the user clicks the confirm button, THE System SHALL validate that the Facecam_Placement is within acceptable bounds.
3. IF the Facecam_Placement is valid, THE System SHALL proceed to apply the placement to all clips in the Clip_Batch.
4. IF the Facecam_Placement is invalid, THE System SHALL display an error message and prevent confirmation.
5. THE Mini_Editor SHALL also provide a "Cancel" button to allow the user to abandon the formatting operation.
6. WHEN the user clicks cancel, THE System SHALL close the Mini_Editor without modifying any clips.

### Requirement 7: Consistent Placement Across All Clips

**User Story:** As a user, I want the confirmed facecam placement to be applied consistently to all clips in the batch, so that the vertical clips have a uniform appearance.

#### Acceptance Criteria

1. WHEN the user confirms the Facecam_Placement, THE Vertical_Formatter SHALL apply the same placement to every clip in the Clip_Batch.
2. THE Vertical_Formatter SHALL use the confirmed Facecam_Region coordinates from the Source_Clip as the basis for all clips.
3. THE Vertical_Formatter SHALL scale and position the facecam identically in each output clip's Vertical_Canvas.
4. THE Vertical_Formatter SHALL scale and position the gameplay region identically in each output clip's Vertical_Canvas.
5. IF a clip in the batch has a different source resolution than the reference clip, THE Vertical_Formatter SHALL proportionally adjust the Facecam_Region coordinates to match the new resolution.
6. THE Vertical_Formatter SHALL process all clips in the batch sequentially or in parallel, depending on system resources.

### Requirement 8: Output File Generation

**User Story:** As a user, I want the vertically-formatted clips to be generated as output files, so that I can use them in my content.

#### Acceptance Criteria

1. WHEN the Vertical_Formatter completes processing, THE System SHALL generate output video files in vertical (9:16) format.
2. THE Output files SHALL have the same filename as the original clips, with an optional suffix (e.g., "_vertical") to distinguish them.
3. THE Output files SHALL be saved to the configured output directory.
4. THE Output files SHALL contain the Facecam_Region overlaid on the Vertical_Canvas with the Gameplay_Region below.
5. THE Output files SHALL preserve the audio track from the original Source_Clip.
6. THE Output files SHALL maintain the same video codec and quality settings as the original clips (or use sensible defaults).
7. THE Output files SHALL be playable on standard video players and compatible with social media platforms (YouTube Shorts, TikTok, Instagram Reels).

### Requirement 9: Original Clip Replacement

**User Story:** As a user, I want the original horizontal clips to be replaced with the vertical versions, so that I don't have to manually manage multiple versions.

#### Acceptance Criteria

1. WHEN the Vertical_Formatter completes processing all clips, THE System SHALL replace the original Source_Clips with the vertically-formatted output files.
2. THE System SHALL create a backup of the original clips before replacement (optional, configurable).
3. IF the user has enabled backup, THE System SHALL store the original clips in a backup directory with a clear naming convention.
4. WHEN replacement is complete, THE System SHALL display a confirmation message to the user indicating the number of clips replaced.
5. THE System SHALL provide an option to undo the replacement if the user is not satisfied with the result (within the same session).

### Requirement 10: Error Handling for Detection Failures

**User Story:** As a user whose facecam is not detected, I want the system to provide clear feedback and alternative options, so that I can still format my clips to vertical.

#### Acceptance Criteria

1. IF the Facecam_Detector fails to identify a valid Facecam_Region, THE System SHALL display a clear error message explaining why detection failed.
2. THE Error message SHALL suggest possible reasons (e.g., facecam too small, facecam too large, no clear pip detected).
3. THE System SHALL offer the user the option to manually select the Facecam_Region by drawing a bounding box on the source clip.
4. THE System SHALL offer the option to use a Fallback_Fill (blurred gameplay) in the top region instead of a facecam overlay.
5. IF the user chooses manual selection, THE Mini_Editor SHALL switch to a manual selection mode with drawing tools.
6. IF the user chooses Fallback_Fill, THE System SHALL apply the fallback to all clips in the batch.
7. THE System SHALL log detection failures with relevant metadata (clip name, detection confidence, area fraction) for debugging.

### Requirement 11: Integration with Existing Clip Pipeline

**User Story:** As a user, I want the Mini Editor to integrate seamlessly with the existing clip generation pipeline, so that the workflow feels natural and cohesive.

#### Acceptance Criteria

1. THE Mini_Editor SHALL be triggered only after the existing clip generation pipeline completes successfully.
2. THE Mini_Editor SHALL reuse the Facecam_Detector logic from the existing pipeline (pipeline.facecam_relocator.FacecamRelocator).
3. THE Mini_Editor SHALL reuse the Vertical_Canvas layout computation from the existing pipeline (pipeline.frame_reformatter.compute_canvas_layout).
4. THE Mini_Editor SHALL reuse the FFmpeg filter generation logic from the existing pipeline for building the final output.
5. THE Mini_Editor SHALL respect all existing configuration settings (canvas dimensions, facecam area constraints, etc.) from the Config object.
6. THE Mini_Editor SHALL not modify or interfere with the existing clip generation pipeline.
7. THE Mini_Editor SHALL be optional — users can skip it and proceed with the original horizontal clips if desired.

### Requirement 12: Performance and Real-Time Responsiveness

**User Story:** As a user adjusting facecam placement, I want the preview to update smoothly and quickly, so that the interface feels responsive and not laggy.

#### Acceptance Criteria

1. THE Preview_Pane SHALL update within 500 milliseconds of any user adjustment to the Facecam_Region.
2. THE Mini_Editor interface SHALL remain responsive (no freezing or blocking) while the Facecam_Detector is running in the background.
3. THE Facecam_Detector SHALL complete its analysis within 30 seconds for a typical 30-second clip.
4. THE Vertical_Formatter SHALL process each clip within a reasonable time frame (e.g., 2–5 minutes per clip, depending on resolution and codec).
5. THE Mini_Editor SHALL display a progress indicator while the Facecam_Detector is running.
6. THE Mini_Editor SHALL display a progress indicator while the Vertical_Formatter is processing clips.
7. THE System SHALL allow the user to cancel long-running operations (detection, formatting) at any time.

### Requirement 13: Web GUI Implementation

**User Story:** As a user, I want the Mini Editor to be a web-based GUI, so that I can access it from any browser without installing additional software.

#### Acceptance Criteria

1. THE Mini_Editor SHALL be implemented as a web GUI (HTML, CSS, JavaScript) served by the existing web server.
2. THE Mini_Editor SHALL be accessible via a URL route (e.g., /mini-editor) on the web server.
3. THE Mini_Editor SHALL support modern browsers (Chrome, Firefox, Safari, Edge) with ES6+ JavaScript support.
4. THE Mini_Editor SHALL use responsive design to adapt to different screen sizes (desktop, tablet).
5. THE Mini_Editor SHALL communicate with the backend via REST API or WebSocket for long-running operations.
6. THE Mini_Editor SHALL display clear loading states and progress indicators during backend operations.
7. THE Mini_Editor SHALL handle network errors gracefully and provide retry options.

### Requirement 14: Support for Both Horizontal and Vertical Source Videos

**User Story:** As a user with both horizontal and vertical source videos, I want the system to handle both formats, so that I can format any clip to vertical.

#### Acceptance Criteria

1. THE Vertical_Formatter SHALL accept source videos in any aspect ratio (16:9, 4:3, 1:1, 9:16, etc.).
2. WHEN the source video is already vertical (9:16), THE System SHALL scale and position it appropriately within the Vertical_Canvas.
3. WHEN the source video is horizontal (16:9 or wider), THE System SHALL scale and position it to fit within the Gameplay_Region.
4. THE Vertical_Formatter SHALL preserve the source video's aspect ratio in all cases (no stretching or distortion).
5. THE Vertical_Formatter SHALL apply letterboxing (black bars) if necessary to maintain aspect ratio.
6. THE Facecam_Detector SHALL work correctly on both horizontal and vertical source videos.

### Requirement 15: Reuse of Existing Facecam Detection Logic

**User Story:** As a developer, I want the Mini Editor to reuse existing facecam detection logic, so that I don't duplicate code and maintain consistency.

#### Acceptance Criteria

1. THE Mini_Editor SHALL import and use the FacecamRelocator class from pipeline.facecam_relocator.
2. THE Mini_Editor SHALL call FacecamRelocator.detect_facecam() to perform automatic detection.
3. THE Mini_Editor SHALL use the same FacecamRegion data model from pipeline.models.
4. THE Mini_Editor SHALL use the same area fraction validation logic (min_area_fraction, max_area_fraction).
5. THE Mini_Editor SHALL use the same corner classification logic (top-left, top-right, bottom-left, bottom-right).
6. THE Mini_Editor SHALL respect all configuration settings from the Config object (facecam_sample_duration, facecam_min_area_fraction, etc.).
7. THE Mini_Editor SHALL not modify or extend the FacecamRelocator class; instead, it SHALL use it as-is.

### Requirement 16: Reuse of Existing Frame Reformatting Logic

**User Story:** As a developer, I want the Mini Editor to reuse existing frame reformatting logic, so that the vertical output is consistent with the existing pipeline.

#### Acceptance Criteria

1. THE Mini_Editor SHALL import and use the FrameReformatter class from pipeline.frame_reformatter.
2. THE Mini_Editor SHALL call FrameReformatter.compute_canvas_layout() to compute the Vertical_Canvas layout.
3. THE Mini_Editor SHALL call FrameReformatter.build_canvas_filter() to generate the FFmpeg filter for the Gameplay_Region.
4. THE Mini_Editor SHALL use the same CanvasLayout data model from pipeline.models.
5. THE Mini_Editor SHALL use the same canvas dimensions and layout split from the Config object (shorts_width, shorts_height, facecam_top_fraction).
6. THE Mini_Editor SHALL not modify or extend the FrameReformatter class; instead, it SHALL use it as-is.

### Requirement 17: Accessibility and User Experience

**User Story:** As a user with accessibility needs, I want the Mini Editor to be accessible and easy to use, so that I can format my clips without barriers.

#### Acceptance Criteria

1. THE Mini_Editor interface SHALL follow WCAG 2.1 Level AA accessibility guidelines.
2. THE Mini_Editor SHALL provide keyboard navigation for all controls (Tab, Enter, Arrow keys).
3. THE Mini_Editor SHALL provide clear labels and descriptions for all UI elements.
4. THE Mini_Editor SHALL use sufficient color contrast (at least 4.5:1 for text).
5. THE Mini_Editor SHALL provide alt text for all images and icons.
6. THE Mini_Editor SHALL announce status updates and progress to screen readers.
7. THE Mini_Editor SHALL allow users to adjust font size and spacing for readability.

### Requirement 18: Undo/Redo Functionality

**User Story:** As a user, I want to undo or redo my adjustments to the facecam placement, so that I can experiment without losing my work.

#### Acceptance Criteria

1. THE Mini_Editor SHALL maintain an undo history of all Facecam_Region adjustments.
2. THE Mini_Editor SHALL provide an "Undo" button that reverts the last adjustment.
3. THE Mini_Editor SHALL provide a "Redo" button that reapplies the last undone adjustment.
4. THE Mini_Editor SHALL support keyboard shortcuts (Ctrl+Z for undo, Ctrl+Y for redo).
5. THE Undo/Redo history SHALL be cleared when the user confirms the Facecam_Placement or closes the Mini_Editor.
6. THE Mini_Editor SHALL display the current undo/redo state (e.g., "Undo (3 steps)" or "Redo disabled").

### Requirement 19: Batch Processing Status and Feedback

**User Story:** As a user processing multiple clips, I want to see the status of each clip as it's being formatted, so that I know the progress and can estimate completion time.

#### Acceptance Criteria

1. WHEN the Vertical_Formatter begins processing the Clip_Batch, THE System SHALL display a progress indicator showing the number of clips processed and remaining.
2. THE Progress indicator SHALL update in real-time as each clip completes.
3. THE System SHALL display the estimated time remaining for the batch to complete.
4. THE System SHALL display the name or identifier of the clip currently being processed.
5. IF a clip fails to process, THE System SHALL display an error message with the clip name and reason for failure.
6. THE System SHALL allow the user to pause or cancel the batch processing at any time.
7. WHEN batch processing completes, THE System SHALL display a summary (e.g., "10 clips formatted successfully, 0 failed").

### Requirement 20: Configuration and Settings

**User Story:** As a user, I want to configure the Mini Editor behavior (e.g., backup options, output naming), so that I can customize the formatting process to my needs.

#### Acceptance Criteria

1. THE Mini_Editor SHALL respect all relevant configuration settings from the Config object.
2. THE Mini_Editor SHALL provide a settings panel where users can configure optional behaviors (e.g., create backup, output naming convention).
3. THE Settings panel SHALL allow users to enable/disable backup of original clips.
4. THE Settings panel SHALL allow users to choose the output naming convention (e.g., "_vertical" suffix, custom prefix).
5. THE Settings panel SHALL allow users to choose whether to replace original clips or save to a separate directory.
6. THE Settings panel SHALL persist user preferences across sessions.
7. THE Mini_Editor SHALL validate all user-provided settings before applying them.
